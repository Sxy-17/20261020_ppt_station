# inbox/ · 用户投料区

**你（人类）往这里丢东西，agent 只读盘点、绝不动你的文件。**

## 可以丢什么

| 类型 | 去向 |
|---|---|
| .ppt / .pptx | 翻新候选（A 路线盘点后由你勾选） |
| .pdf / 论文 / 代码 / 技术报告 | B 路线素材（登记备用） |
| .md（项目管理导出的时间线等） | 叙事流素材 |
| 图片 | 素材登记 |
| 其他 | 忽略但登记在盘点清单 |

## agent 的规矩（写给接手的 AI）

1. 盘点时先过滤垃圾：`~$` 开头的 Office 锁文件、临时文件
2. 子目录递归扫描；同名异目录文件在清单里标出让你确认
3. 盘点结果只做**轻体检**（毫秒级元数据读取），重活等用户勾选
4. 本目录唯一的写操作 = **收编搬运**：素材被任务消费时移出 inbox——
   翻新候选入 `projects/<任务>/sources/`，B 素材入 `projects/<任务>/materials/`，
   并写 `projects/intake_ledger.json`（原始路径/去向，可审计可回退）。
   **inbox = 当前工作集**：被消费即搬走，物理上不存在历史残留，
   根绝"新任务把旧素材语义带进去"的污染。取消任务按登记簿搬回。
   除此之外一律只读，处理产物全部写进 `projects/`
5. **素材边界规则**：B 路线素材范围 = 当前 inbox + 用户点名的路径；
   绝不私自去 `projects/` 翻旧任务素材（复用需用户点名，从旧任务拷贝）
6. 用户按子文件夹归类投放（如 inbox/季度汇报/）自然支持（递归+整目录搬），
   但纯属便利，不是正确性依赖
