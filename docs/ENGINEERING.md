# 工程教训与规范（ENGINEERING.md）

> 给下一个建设 agent：**开工前读一遍**；每犯一个新失误/立一条新规矩，当日追加本文档（只增不删，像审美库一样）。
> 规范编号 R*（rule），失误编号 #N（incident）；失误条目必须写明"→ 固化 R*"。

## 一、工程规范 R1–R14

| # | 规范 | 为什么 |
|---|---|---|
| R1 | **用户区不可侵犯**：`inbox/`、`projects/`真实任务、`ref/`、`library/` 永不删除；测试一律 `tmp/`（gitignored） | 误删事件 #1 的代价 |
| R2 | **清理只点名**：rm 必须指向具体路径，删前 `ls` 看内容；禁止通配删除用户区任何东西 | 同上 |
| R3 | **原始输入（sources/）与产出（exports/）永不删**：中间产物（original.png/text.md）可再生，重生成脚本在 `station/prep/` | 用户底线：至少输入输出留着 |
| R4 | **commit 即 push**；push 失败（网络）必须记录待推提交号，恢复后立即补推 | 远程即备份，不堆积 |
| R5 | **幂等优先**：准备链脚本全部幂等 + `--force` 强制重跑 | 链会被反复重跑，重跑不能炸或重复产出 |
| R6 | **COM 规范**：`DispatchEx` 独占实例（不劫持用户开着的 PowerPoint）；`WithWindow=False` 无窗（不碰 `Visible`，部分版本抛错）；**路径一律 ASCII**（收编时已统一改名 `source.*`，ref 教训） | COM 坑全是经验坑 |
| R7 | **私有访问要局部+注释**：python-pptx 读 `_element`/XML 标签处（连接线 cxnSp、隐藏位 show）必须注释为什么，且集中在 classify 一处 | 上游无 API 时的下策，要把下策围起来 |
| R8 | **Windows 控制台中文**：脚本开头 `sys.stdout.reconfigure(encoding="utf-8")`；heredoc 测试脚本同样要 | 否则中文输出变问号/乱码（#9） |
| R9 | **轻重分级**：批量扫描只读元数据（毫秒级，zip/XML 直读）；COM/重活只对用户勾选件跑 | 20 个文件秒级出清单靠这个 |
| R10 | **显示语义一致**：输出文案/标签/路径必须从真实值派生（`relative_to`），禁止写死 | "同系组×1""projects/t1"两次谎话 |
| R11 | **检测器要角色感知**：缺陷判定（空页/拥挤）先看页面角色——封面/隔页/致谢天生稀疏，不是病 | #4 #5 |
| R12 | **启发式常量顶部集中**：阈值/关键词写在文件头常量区，注释"初判可被 agent 看图覆盖" | 改启发式不用翻代码，且明确它是猜测不是判决 |
| R13 | **不提前抽象**：第二次用例出现才收敛复用（`read_theme` 从 inventory 复用到 diagnose 就是案例） | AGENTS.md 铁律的执行版 |
| R14 | **换行统一 LF**：`.gitattributes` 已配，禁止局部关掉 | CRLF 警告噪音 #7 |
