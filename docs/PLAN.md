## 0. 一页纸总览

```
用户对话提到"更新/翻新PPT"
   ↓ 语义识别（内容可保留，模板/图/排版不行）
   ↓ 收件箱盘点（多文件场景，见 §2.1）：轻体检→归类型→同模板系分组→用户勾选
   ↓ 准备链+诊断（仅对选中件，后台跑）：截图/抽文字/建页目录 + 体检
   ↓ 确认包 = 诊断报告+处方（三通道，见 §2.2）：①选择页点选 ②聊天快答 ③你定→试稿
   ↓ agent 按审美库生成全部页 SVG 初稿
   ↓ 弹出审核工作台网页
左=原页PNG    右=新页SVG（可编辑）   底=裁决条+意见框
   ↓ 手动微调 或 意见框大白话→agent改→刷新
   ↓ 全部裁决完 → 聊天里说"导出" → svg_to_pptx → 原生可编辑 .pptx
```

核心不变式（三条纪律，写进 SKILL.md）：
1. **确认完再弹**：弹工作台前，所有决策已通过①选择页点选 / ②聊天快答 / ③明确委托（"你定"）之一完成；网页运行中 agent 不再主动追问，只消化意见框。委托后 agent 的选择在工作台里全部可见可改。
2. **沉默不确认**：网页上没点的裁决不算数；agent 永不替用户拍板（明确委托除外，委托也是用户主动按的）。
3. **网页不碰导出**：编辑器只改中间形式（SVG），导出永远由用户在聊天里发起。

## 1. 技术决策（工程层，我负责）

### 决策 A：中间表示 = 规范化 SVG（ppt-master 方言），不自研 PPT 引擎

| 候选 | 结论 | 理由 |
|---|---|---|
| 网页嵌真 PPT 引擎（Office Online / 腾讯 slidep） | ❌ | slidep 是内部工具不可控（你 ref 里踩的路径坑、中文文件名坑就是证据）；Office Online 需服务端 |
| 只读图片渲染 + 全靠 prompt 改 | ❌ | 你明确要"右边可直接上手编辑" |
| **规范化 SVG 中间形式 + svg_to_pptx 编译导出** | ✅ | ppt-master 的核心哲学：审核所见=导出所得；文本/形状/图片导出后全是原生可编辑对象 |

**含义**：右框是浏览器里的 SVG 画布（本机字体直接可用，字体度量用 ppt-master 的 text_measure.py 思路），导出后每个文本框/图形/图片都是 PowerPoint 原生对象——可改字、改色、改大小，字体与本地一致。

### 决策 B：左侧原 PPT = 逐页高清 PNG（只读）

准备链用 Windows Office COM（PowerPoint 自动化）把旧课件逐页导出 PNG。不做旧 PPT 的可编辑回放——左侧的职责是"对照+保底贴图"，可编辑性由右侧新稿承担。

### 决策 C：网页 = 单个常驻 Flask 服务（station/server.py）

模式抄 ppt-master 的 confirm_ui + svg_editor：
- 每任务一把锁（lock.json 记 pid+端口），重复启动复用不报错
- 所有状态是文件：project.json / pages/NNN/verdict.json / pending_requests.jsonl
- 网页与 agent 通过文件传话，聊天等价性天然成立（不开网页 = 聊天里说，流程一样走）
- 未保存编辑永远先落 draft（防丢）

### 决策 D：动效 = animations.json + Morph 配对页（已验证可行）

- 元素动画：`entrance_fly`(各方向)/`entrance_expand`/`emphasis_*`/`path_*`…100+ 原生效果，侧车文件声明，编译成原生 XML → **导出后在 PPT 动画窗格可改时长/顺序/触发** ✅
- "逐渐展开的时间轴" = Morph：相邻两页做成时间轴的两个状态 + 配对声明，PowerPoint 自动插值
- 动效默认关（反 AI 味纪律），按页需要开启；好看的动效组合沉淀为 `type: motion` 审美 .md

### 决策 E：不采用 workbuddy/slidep 路线，但吸收其思想

ref/SKILL.md（paper-to-deck）写得很好，四条信念直接吸收进审美库的页面角色类：
- 论文的图就是最好的图（不 AI 生图）
- 数据只在效果页出现
- 相邻页版面结构必须不同
- 大数字锚点
slidep 引擎本身弃用（内部工具、路径/中文文件名坑、不可维护）。

## 2. A·PPT 翻新：UX 详案（你重点审这节）

### 2.1 触发（聊天 → 识别 → 收件箱盘点）

用户说"更新这批PPT""翻新一下""这个模板太老了"等 → agent 判定语义（大量内容可保留、模板/图/排版不行）→ 直接盘点收件箱，**此时不问任何问题**。

**收件箱约定 `inbox/`**（用户随手丢，agent 先盘点再干活）：
- 类型路由：PPT→翻新候选；PDF/论文/代码/.md→素材登记（B 路线备用）；图片→素材库；未识别→忽略但登记。只读不动用户文件
- 自动过滤：Office 锁文件（`~$`开头）、同名异目录、子目录递归

**轻体检 vs 重准备链（成本分级）**：盘点时对全部候选跑**轻体检**（毫秒级/文件：页数/画幅/主题色/修改时间，只读元数据）；**重准备链**（逐页截图+抽取+诊断）只对用户勾选的跑。盘点清单示例：

> 📦 收件箱盘点：**14 个 PPT 同一套模板**（2023 科研汇报系，蓝 4:3）· 3 个独立件 · 2 篇论文 · 1 个时间线 md
> 本次翻新：[同模板系 14 个批量◆] [我自己挑]

**同模板系批量共享处方**：轻体检发现主题色/画幅一致→归为一个"系"→一份诊断+一份处方+一次确认，批量建任务目录排队跑准备链（"一大批"场景不是问 14 遍）。

**收编制（inbox 生命周期）**：inbox = 当前工作集，被消费即物理搬走——翻新候选入 `projects/<任务>/sources/`，B 素材入 `projects/<任务>/materials/`，登记 `intake_ledger.json` 可回退。根绝旧素材语义污染；复用旧素材需用户点名（从旧任务目录拷贝）。B 选择页第一次弹的素材盘点清单即勾选确认（哪些进本次）。子文件夹归类是便利非依赖。

> ✅ UX-1 已定：**诊断先行**——准备链不只抽内容，还提取模板/图/排版信息，确认包以"诊断报告+处方"形式给出，用户只做 double-check（见 §2.2）。

### 2.2 确认包 = 诊断报告 + 处方（三通道，打字量递减）

准备链除了抽内容，还做**体检**（机器可测的交给脚本，微妙的人工判断交给 agent 看截图）：

| 诊断项 | 怎么得来 |
|---|---|
| 画幅、主题色板、主题字体 | 脚本读 pptx 主题/形状填充采样 |
| 框线图/流程图页清单及风格统计 | 图形元素计数（递归展开组合形状）+ agent 看截图定性 |
| 版式问题信号（溢出/拥挤/无对齐/缺页眉页脚） | 文字量启发式 + agent 看截图 |
| 图片质量信号（低清/AI味/风格不一） | agent 看截图 |

诊断落盘为 `diagnosis.json`。确认包先给诊断，再给**处方**（每项带◆推荐，理由来自诊断）：

> 📋 诊断·37 页：4:3 · 主色蓝#1F4E79 · 微软雅黑 | 框线图 9 页（3 页手绘风+6 页默认形状，风格不统一）| 12 页文字拥挤 | 11 页缺页脚
> 💊 处方：学术·现代 16:9◆（科研汇报场景）· 图形页重绘优先◆（9 页风格不一，重绘统一）· 全部 37 页◆

以下三通道任选其一完成确认（确认后→生成初稿→弹工作台）：

**① 选择页点选（默认，零打字）**——弹轻量选择页（复用 station 服务，比工作台早一步）。**形态**：一次性表单式确认页，`/select` 路由自动开新标签页，一屏装完（诊断区+处方区+双大按钮[✦你定先出10页看看]/[就这样出稿→]），全点选件，提交后即焚可关；agent 阻塞等待（同 confirm_ui 模式），超时转聊天通道②；收据落盘 selection.json；复用工作台设计系统（深色 tokens/8px 网格）。三个内容变体同壳：A确认包（表单）/B素材处方（表单）/B大纲确认（可拖拽卡片流）：
- 风格：模板卡片（色板条+字体样样张+一句话纪律），点选高亮
- 画幅 16:9/4:3、页面范围（全部/前N页/自定义段）、图形页策略（重绘优先/保留原图/全部重绘）、动效（无/轻入场）
- 每项带 ◆推荐标记（基于 agent 看过的页面统计预选好，多数情况直接点"就这样，出稿"）
- 另有黄色按钮：**[你定，先出 10 页看看]** → 走通道③

**② 聊天快答（等价通道）**——不开网页时，同一确认包压成一行选择题：
> 风格: 1学术·现代◆ 2编辑部 3深空 4瑞士红 | 画幅: A16:9◆ B4:3 | 范围: 全部◆/页段 | 图形页: 重绘◆/保留
> 回"1A"即可；逐项缺省用推荐值。

**③ 完全委托（懒人通道）**——点"你定，先出10页看看"或聊天说"随便/你定"→ agent 按全部推荐值出 **10 页试稿** → 直接弹审核工作台（试稿就是货）→ 顶部一键换模板可全部重出 → 满意后批量出剩余页。

试稿机制一石二鸟：既是懒人通道的出口，也是风格定调手段（对应 UX-5）。

确认完成 → 生成初稿 → 弹工作台。

### 2.3 审核工作台（网页主界面）

```
┌────────────────────────────────────────────────────────────┐
│ 任务名 | 学术·现代·16:9 [改模板⚙重出]  [单页|总览]  ◀ 24/101 ▶│
├──────────────────────────┬─────────────────────────────────┤
│  原页（PNG，只读，同缩放） │  新页（SVG 画布，可编辑）          │
│                          │  [撤销][适配][+文本框][+形状]     │
│                          │  [+图片][✦美化选中][删除][保存]   │
├──────────────────────────┴─────────────────────────────────┤
│ [框线图] ○保留原样 ○通过当前稿 ●审美引擎重绘◆推荐            │
│ [意见框：大白话描述 → 提交]（写入待办队列，agent 异步消化）    │
│ [保存裁决并下一页]（翻页即自动保存）                          │
└────────────────────────────────────────────────────────────┘
```

**右侧编辑器能力清单（v1）**：
- 拖动移动 / 拖角缩放 / Del 删除 / 方向键微调(1px, Shift=10px)
- 双击改字（字体族=本机字体下拉，字号/颜色/加粗）
- **新建**文本框 / 矩形·圆形·线条 / 插入本地图片
- Ctrl+Z 撤销；改动 staged，翻页/裁决时自动落盘
- ✅ 新建形状（UX-3 已定）：矩形/圆/线条三件套；复杂图形（箭头组、流程框、时间轴等）走意见框让 agent 画

**✦ AI 美化选中（粗画→美化，sketch→polish 模式）**：
- 你用三件套+文本框**粗画结构**（歪框歪箭头都行，位置/包含/连线就是语义）→ 框选 → [✦ AI 美化选中] → 可选补一句提示（"横向流程""间距大点"），不填直接点也行
- 走异步流水线：提交即翻页 → agent 按模板色板+图形配方重画选区 → 顶端横幅提醒
- agent 硬约束：**文字一字不改**；**拓扑保真**（左右序/包含/连线保留，粗画是结构契约）；视觉语言全换（对齐网格/节点样式/箭头语言/着色）；整次美化=一条撤销记录
- **技术形态**：美化产物=同页 draft.svg 里的规范化 SVG 元素（预设轮廓标记+真`<text>`，不转曲线不贴图）——单一中间形式不变式，保证美化后仍可编辑、可撤销、可导出原生对象
- 副产品：用户认可的美化结果 → agent 主动提议沉淀为 diagram-recipe 审美 .md（图形配方库最肥进料渠道）

**意见框（prompt 微调通道，异步流水线）**：
- 你写"这里做个逐渐展开的时间轴，标 2023立项/2024中期/2025结题，风格跟整体一致" → 提交进 `pending_requests.jsonl` → **立即翻下一页继续审，不等待**
- agent 后台消化：改 SVG（时间轴）+ 动效配方（Morph 配对/入场序列）→ 写回该页草稿
- 完成后**页面顶端滑出横幅提醒**（非弹窗）："1 条意见已消化：P24 时间轴已重画 [查看对比]"；右上角铃铛累计"N 条已消化"，点击展开改动页列表可跳转
- 若你在改动页停留，刷新该页时提示"此页已被 agent 更新，[查看新版本]"，避免正在编辑时被覆盖（编辑中不自动刷新）

**裁决三选一语义**（同任务书）：保留原样=PNG 直接进新 PPT（图绝不丢的保底）；通过当前稿；重绘=agent 照左图按图形配方重画可编辑矢量图。

### 2.3A 工作台 UX/UI 基准（世界前沿清单，硬性约束）

> v1.1：本节不再是硬性约束。总览、批量裁决、命令面板、胶片条、滑杆/Tab 对比、★回看、版本历史 UI、✦美化选中、动效角标均从工作台移除（§8.2 D4），视觉规范以 §8.8 为准。

> 对标：对比审阅→Lightroom/VS Code diff；画布编辑→Figma；命令可达→Linear/Raycast；协作反馈→Google Docs。桌面优先（键盘+鼠标），无移动端。

| 组 | 采用的世界级模式 | 分期 |
|---|---|---|
| **对比与聚焦** | ①并排（默认，缩放/平移双面板联动）②**滑杆分割**（拖动分割线，左原图像素/右新稿同位渲染，查"图丢没丢"杀手锏）③**Tab 闪烁对比**（按 Tab 两面板瞬时互换，人眼秒辨差异，天文学家变星比较法）| 模式①③→M3；②→M4 |
| **键盘与命令** | **Cmd/Ctrl+K 命令面板**（跳页/换模板/裁决/筛选/插入形状/导出，全部动作可搜可达）；`?` 快捷键浮层；`1/2/3` 裁决、空格/Shift+空格翻页、Esc 逐层退出；无鼠标可走完全部流程 | M3 |
| **画布编辑** | 8 向手柄+旋转柄；**智能参考线吸附**（对齐兄弟元素/页边，红色对齐线）；Alt+拖动=复制；输入框支持算术（`x: 120+40`）；数值标签可拖拽改值；空格+拖动平移；Ctrl+滚轮缩放至光标；Shift+1 适屏/Shift+2 缩至选区/0 回 100% | 基础→M4；参考线距离显示→polish |
| **状态与信任** | 自动保存指示（"已保存·刚刚"）；**agent 正在改此页"的实时徽标**（三点呼吸动画，Google Docs 在场威示感）；每页版本历史 popover 可回退；失败横幅+重试；**乐观 UI**（裁决先本地生效，落盘异步） | 徽标/保存→M3；版本历史→M4 |
| **导航与批量** | 单页模式底部**胶片条**（Lightroom 式，缩略图快速跳转，虚拟化渲染千页不卡）；总览网格虚拟化；**★回看旗标**（"这页待定再回来"，超越三选一的第四态，可按★过滤）；顶栏进度条按裁决色分段（101 页一眼看清还剩多少） | 胶片条/进度→M3；★旗标→M3 |
| **视觉与动效** | **深色中性外壳**（#111418 系，页面内容凸出、UI 隐退，Lightroom/DaVinci 同理）；8px 网格 + 设计 tokens（色/距/字阶集中定义）；翻页 200ms 交叉淡化；骨架屏；空状态必带下一步动作；尊重 prefers-reduced-motion | M3 |
| **性能预算** | 首屏 <1s；相邻页 PNG/SVG 预取（预测翻页方向）；网格虚拟化；画布直接 DOM 操作 60fps；无构建链（原生 ES Modules+CSS tokens，靠交互设计质量而非框架堆料，守住 AGENTS.md 可维护性） | 全程 |
| **无障碍** | 键盘全可达；focus ring 不去除；ARIA 标注；中文一等公民（字体/度量/换行） | 全程 |

图标统一 Lucide 风格线形 16px；状态色语义全站一致（未裁决灰/通过绿/保留蓝灰/重绘紫/有意见琥珀点/★回看金）。

**批量裁决（总览模式，采 Gmail/Lightroom 成熟模式）**：
- **筛选片**：全部/未裁决/已通过/图形页/有我的编辑/有待消化意见，带计数
- **多选**：单击、**Shift+点选范围**（即"第5到20页"的自然形态）、Ctrl+追加、Ctrl+A 全选当前筛选
- **批量操作条**：已选 N 页 → [通过][保留][重绘][清除裁决]；已裁决页默认跳过，可选覆盖；一次批量=一条撤销记录
- **范围直填**：`[范围: __ 到 __]` + 裁决按钮，缩略图未加载完时敲页码更快
- **单页快捷键筛片**：单页模式下 `1`保留 `2`通过 `3`重绘 `空格`下一页，逐页压到一次击键
- **聊天等价**：批量也是写 verdict.json，聊天说"5–20页全部通过"同样有效；每笔批量记入 batch_log.jsonl 可审计
- 总览缩略图=新稿小图+状态角标（✓通过 ▣保留 ✦待重绘 ●未裁决），点击进单页

### 2.4 聊天↔网页：双入口单队列，agent 生命周期

- **网页≠agent**：工作台/选择页背后是 Flask 常驻小进程（后台daemon）；agent 始终在聊天框里，弹出网页后随时可说话（改页/批量/问进度）——聊天永远是第一入口
- **网页无通用聊天框**（v1 不做）：意见框=页级结构化请求，与聊天里说"第5页加时间轴"进同一队列（双入口单队列）
- **消化时机**：会话中你丢任何一个字（"继续"）→ agent 消化队列→横幅提醒；不说话则队列安静躺着；新会话说"继续 projects/xxx"可接手（SKILL.md 路由恢复）
  - v1.1：增加「值守模式」，agent 出稿后阻塞等待队列，网页提的意见无需再去聊天里说"继续"，见 §8.6
- **镜像成立：不开聊天也能审**——浏览/裁决/编辑/提意见均为本地文件操作，不依赖 agent 活着；仅"让 AI 改"需要 agent
- 一句话：**聊天是全功能的，网页是快捷的，文件是唯一的真相**

### 2.5 收尾

全部裁决完 → 聊天里说"导出" → 编译 pptx（通过页=原生排版，保留页=贴图，重绘页=矢量）→ 告知路径。中途随时可断，裁决全在盘上。

## 8. v1.1 修订：A 路线审核工作台重构（2026-11-02，用户批准）

> 来源：`ref/重构需求书_UIUX.md`。诊断报告、重构方案和可交互原型的完整版放在 `tmp/uiux_refactor/`（gitignored，可能被清理），本节是入库的权威版本。

### 8.1 为什么重构（诊断摘要）

- **编辑器从 M4.3（a0473f3）起没在浏览器里加载过**：`station/static/edit.js` L52、L531–535、L543–544 的字符串里写进了真实换行，整个文件是语法错误。7d13944、a0adc76 能过 `node --check`，a0473f3 起全部失败。M4.3–M4.9 都没在浏览器里跑过。
- **就算修好语法，也挂不上当前页**：`render()` 是 async，edit.js 在新稿换进来之前就同步绑定事件；覆盖层挂在 `#draft-holder` 里，翻页时被 `innerHTML` 清掉。
- **流式出稿会打断审核**：⚡ 的轮询每出一页就 `loadTask()`，会跳回第一个未裁决页；`pollNewDrafts` 会重载当前页，丢掉未保存的编辑。
- **翻页竞态**：没有请求序号，快速翻页时右栏可能显示的不是当前页。
- **导出不读裁决**：`export.py` 不读 `verdict.json`，「保留原图」不生效，未裁决页也照样导出。
- **agent 改稿后右栏不刷新**：轮询签名只看 `has_draft`/`verdict`，不看稿件内容。
- **其他**：3 个文件链式改写 `window.render`；101 份 SVG 内联进同一 DOM，id 互相冲突；拖动后 `data-pptx-bounds` 不更新；Delete 是空实现；批量撤销必抛 TypeError；存稿先覆写再质检；上传文件名未清洗；用 `alert`/`prompt` 报错。
- **UX**：单页常驻 19 个控件 + 101 张胶片缩略图，主路径被淹没；跳页有 6 个入口；编辑要先进"模式"。

**不回退 git**：73b97e8 之后后端、资产和前端交织在同一批 commit 里。做法是保留后端，只重写 `station/static/` 的工作台前端；后端只做 §8.5 列出的修改。

### 8.3 信息架构

```
┌──────────────────────────────────────────────────────────────────────┐
│ 课件名   P12 / 101   ■■■■■■■■□□□□······（页带：一页一格，可点）     ⋯ │  顶栏 44px

└──────────────────────────────────────────────────────────────────────┘
```

常驻控件 6 个：页带、三个裁决键、意见框、「⋯」菜单（一键出稿 / 导出状态 / 快捷键）。

**页带**取代进度文字、分段进度条、◀▶、页下拉、胶片条、总览和命令面板。格子含义：浅灰空心=生成中；灰=待审；绿/蓝灰/紫=通过/保留原图/重绘；橙点=有意见在处理；白框=当前页。悬停显示「P23 · 标题 · 状态」。点顶栏的「P12」可直接输入页码跳转。

### 8.4 交互规则

**裁决（三键 + 自动前进）**
- `1` 保留原图：写 keep，跳到下一个未裁决页。
- `2` 通过：有未保存编辑时先保存（过质检门）；质检不过就留在本页，把问题元素标在画布上。通过后写 pass，跳到下一页。
- `3` 重绘：写 redraw，**同时追加一条队列项**（type=redraw），光标进意见框，可写重绘要求也可留空，回车后跳到下一页。
- 对已裁决页再按同一个键 = 撤销裁决（取代「清除」按钮）。
- 下一个未裁决页如果还在生成，右栏显示「P13 生成中…」，出稿后自动显示。

**编辑（右栏）**
| 操作 | 方式 |
|---|---|
| 选中 | 单击 = 鼠标下那一个对象（一个文字框 / 一个框 / 一条线，即导出后的一个 PPT 形状）；Alt+单击或属性条「整组」= 所在根级语义组；Esc 取消（2026-11-02 用户反馈修订：原为单击选整组，只能整体改属性） |
| 移动 | 已选中再按住拖动；方向键 1px，Shift+方向键 10px。选中能装东西的框（rect 等）时，完全落在框里的对象一起移动/删除（虚线标出），框外标签和连线不动 |
| 两栏宽度 | 拖两栏中间的竖条调左右比例（各至少 20%），双击恢复一半一半；比例记在浏览器里 |
| 缩放 | 拖右下角柄（等比，左上角固定） |
| 改字 | 双击文字原位编辑；浮动属性条改字号 / 颜色 / 加粗 |
| 删除 | Delete |
| 新建 | 右下角「+」：文本 / 矩形 / 图片（上传），自动放在不与现有组重叠的位置 |
| 撤销 | Ctrl+Z（按页记录，连续改同一属性合并为一步） |
| 保存 | Ctrl+S，或按「2 通过」时自动保存 |

- 保存链路：烘焙 transform 到几何属性 → 同步更新 `data-pptx-bounds` → 带上基准版本提交（§8.6）→ 服务端写临时文件 → `qc.py` → 原子替换（留 .bak 和版本）。
- 离开有未保存编辑的页时自动尝试保存；质检不过就留在原页并提示，不静默丢弃。
- 防丢（决策 C）：未保存编辑每次变化 1 秒后写 `pages/NNN/draft.wip.svg`（不过质检）。重新打开该页时提示「恢复 / 丢弃」。保存或丢弃后删除。导出器和 agent 只认 `draft.svg`。

**意见与提醒**
- 意见框永远对应当前页，回车提交，框尾显示「agent 处理中（N）」，页带该格出橙点。
- agent 改完：顶部横幅「P7 已按意见改好 · 查看」，8 秒后自动消失。
- 用户正停在被改的页：没有未保存编辑 → 直接载入新稿并闪一下边框；有未保存编辑 → 横幅「agent 更新了此页：载入新稿 / 保留我的修改」，不自动消失。
- 后台出稿只点亮页带，**永不跳页、永不重载当前页**（唯一例外：当前页正处于"生成中"等待状态）。

### 8.5 组件与后端改动

**前端**（一个页面、一个状态对象、一个渲染入口，不链式改写 `render`；`select.html`、`outline.html` 不在本次范围）

| 文件 | 职责 |
|---|---|
| `index.html` | 骨架 |
| `style.css` | 设计 token + 布局 |
| `app.js` | 状态、加载页、翻页（带请求序号，丢弃过期响应）、裁决、意见、横幅 |
| `stream.js` | 唯一轮询（3s）：页清单 + 意见队列，按 `draft_mtime` 比对，只更新页带，冲突时发提示 |
| `editor.js` | 选中/拖动/缩放/改字/新建/删除/撤销/烘焙/保存/wip |

页带不用缩略图；以后如需缩略图，一律 `<img src=draft>`，不内联 SVG（隔离 id）。

**后端**

| 改动 | 原因 |
|---|---|
| `GET /pages` 每页加 `draft_mtime`、`pending` | 流式刷新判断稿件变化；页带橙点 |

| 上传文件名用 `secure_filename`；`_gen_status` 按任务分开 | 安全与多任务正确性 |

### 8.6 并发与 agent 回路

**谁写什么**

| 文件 | 网页 | `batch_draft.py` | agent（重绘 / 消化意见） |
|---|---|---|---|
| `pages/NNN/draft.svg` | 保存时写 | 只写还没有稿的页（L236 跳过已有稿） | 写被点名的页 |
| `verdict.json` | 写 | 不碰 | 不碰 |
| `pending_requests.jsonl` | 追加 | 不碰 | 改状态为 done |

- 批量出稿与网页不冲突：网页能编辑的页一定已有稿，批量脚本不碰。
- 网页与 agent 可能同改一页：原先谁后写谁赢。修法是**统一写入口 + 乐观并发**：
  - 新增 `station/prep/write_draft.py <task> <page> <svg文件> --base-mtime <t>`：校验基准版本 → qc → 原子替换 → 存版本。agent 改稿一律走它，不直接写 `draft.svg`。版本不一致时退出码非 0，agent 重新读稿再改。
  - 网页 `POST /draft` 调用同一套逻辑；409 时前端弹「载入新稿 / 保留我的修改」。
- 意见队列：agent 只通过 `POST /requests/update`（或等价脚本）改状态，不直接编辑 jsonl；服务端加锁。

**意见如何回到 agent（值守模式）**
- 原来：网页意见只写进队列，agent 不会收到通知，要等用户在聊天里说话才去读。
- 现在：agent 启动出稿后（批量出稿在后台子进程里跑，不占 agent）进入循环：
  1. 调 `station/prep/wait_requests.py <task> --timeout 600`，阻塞到出现新的 queued 项（意见或 redraw），输出这一项的 JSON；超时退出码非 0。
  2. agent 读 `original.png`、当前 `draft.svg`、意见文字，改稿，经 `write_draft.py` 落盘，再把该项标为 done。
  3. 回到第 1 步。
- 优先级：用户意见 / redraw 先处理，空闲时再做复杂页重绘。agent 单线程，正在处理的页做完才轮到下一条。
- 超时（默认 10 分钟无新项）后 agent 结束值守，回到"在聊天里说继续"的方式。用户随时可在聊天里打断，聊天仍是第一入口。
- 代价：值守期间这一轮 agent 一直开着，持续消耗额度。
